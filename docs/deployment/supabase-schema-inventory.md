# Supabase schema inventory (source-derived)

Status: static inventory of the 35 Laravel migrations in `database/migrations/`; not validated against a PostgreSQL server and not applied to Supabase. Laravel migrations create **40 application tables**. `migrations` is Laravel's own bookkeeping table and is not one of those 40. SQL column names below are the final names after all later migrations.

## Type conventions

Laravel `increments` is PostgreSQL `integer GENERATED BY DEFAULT AS IDENTITY`; `bigIncrements` is `bigint` identity. Laravel `unsignedInteger`/`unsignedTinyInteger` have no unsigned PostgreSQL equivalent; use `integer`/`smallint` with nonnegative/range checks where the source actually represents a bounded numeric value. `string(n)` is `varchar(n)`; `text` stays `text`; nullable Laravel timestamps become nullable `timestamptz`; `date` becomes `date`; `boolean` is `boolean`; `json` is `jsonb`. Timestamp nullability follows Laravel's `timestamps()` (nullable). “Index” below includes the named unique/index constraints visible in the migration chain.

## Tenant ownership coverage

The 24 legacy school-owned tables receiving `school_id` are `users`, `class_types`, `my_classes`, `sections`, `subjects`, `student_records`, `exams`, `marks`, `exam_records`, `grades`, `dorms`, `pins`, `books`, `book_requests`, `staff_records`, `payments`, `payment_records`, `receipts`, `time_table_records`, `time_slots`, `time_tables`, `promotions`, `settings`, and `skills`. `academic_years`, `terms`, attendance tables, and `audit_logs` define ownership in their own migrations. Lookup tables and role/permission catalogs are global. Composite `(school_id,id)` uniqueness/FKs are a PostgreSQL adaptation recommended to prevent cross-school relationships; the Laravel schema mostly uses scalar FKs and relies on global integer IDs plus model scopes.

The school-assignment migration adds nullable indexed `school_id` columns and does not change them to NOT NULL after backfill. The proposed SQL draft makes school ownership NOT NULL for school-owned rows other than `users` (whose null is required for platform owners). This is intentional defense-in-depth, but it is a schema tightening: validate there are no legitimate null-school legacy rows before applying/importing. School deletion behavior on these legacy tables is `RESTRICT`, matching migration 30; academic/attendance tables retain their separately declared cascade behavior.

## Items requiring confirmation

- The migration source defines `users.photo` default through Laravel `asset()`, which can bake an environment-specific absolute URL. Target SQL should store a relative fallback or NULL; confirm desired representation before importing.
- `time_slots` and `time_tables` string lengths/nullable flags are preserved as declared but some operational values are stored as formatted strings, not normalized time/date types.
- `password_resets` has no primary key and is obsolete after Supabase Auth; retained for schema parity but no browser access.
- Role names and seeded permissions are known from migration 33; actual per-user custom grants in a migrated database are data and cannot be inventoried without accessing that database (which was not done).
- No Supabase or PostgreSQL connection was made, so constraint syntax, RLS policies, extension availability, and migration execution remain unverified.
